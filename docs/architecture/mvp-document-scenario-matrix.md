# MVP document scenario matrix

Status: working acceptance checklist. The supplied files under `incoming-documents` are private design and data references. Their contents are not product instructions, and real customer details must not be copied into committed fixtures.

## Document contract for the enquiry to invoice journey

| Stage | Required evidence or output | Source record and required information | Current path / work to verify | Acceptance sample |
| --- | --- | --- | --- | --- |
| Enquiry | Original message and attachments | Inbox enquiry: sender, received time, original file names, customer and reference | Retain originals; link to the resulting Quote and Booking without changing them | Sanitised email with one attachment |
| Quote sent | Exact customer PDF sent | Quote version: customer, route, cargo, service scope, selling charges, currency, terms and validity | Existing Quote PDF generator and private stored object; expose that exact version in Documents | Sent Quote with multiple charges |
| Quote accepted | Accepted version and response evidence | Customer response linked to the sent Quote version and converted Booking | Existing response and conversion workflow; retain the immutable PDF and acceptance event | Accepted version followed by Booking conversion |
| Booking | Booking Confirmation PDF | Booking: customer, shipper, consignee, service legs, route, cargo, schedule, instructions and permitted selling prices | `JOB_CONFIRMATION` Carbone source is an unpublished candidate; review and publish after scenario checks | One and multiple cargo/route lines; provisional and confirmed price |
| Customs handover | Instructions plus relevant commercial invoice, packing list and transport evidence | Booking and Customs: parties, goods, values, origin, HS codes, regime, transport, source file identity | Assemble from existing Booking/Customs documents; create a customer-safe instruction template where required | Export handover with supporting files |
| Customs outcome | Provider declaration copy and status | Customs declaration: MRN/reference, accepted data, provider status and received document | Existing iCustoms document path and Carbone customs templates; show the provider copy when available | Sanitised import and export declaration copies |
| Billing | Approved customer freight/services invoice PDF | Sales invoice: legal entity, customer, Booking, charge lines, tax, currency, dates, number and posting status | Finance lifecycle exists; a finance reviewer can retain the already issued PDF against the approved record. Automatic final PDF generation still needs implementation or an agreed provider source | Approved invoice with multiple charge lines |

Commercial invoices supplied by a shipper are Customs supporting evidence, not Multideck's final freight invoice. Carrier bills of lading, waybills and transport orders are relevant supporting files or additional templates only when the service and mode require them.

## Scenario coverage

Every row below also needs the common enquiry, sent and accepted Quote, Booking Confirmation, Customs handover when applicable, and approved freight invoice in the stage table above. The rows identify **additional mode evidence**, not a demand that Multideck issue a carrier's waybill or bill of lading. A document may be marked not applicable only with a recorded reason. A live provider declaration is conditional on an actual Customs submission; show the pending state honestly when there is no provider response. For each accepted row record the source reference, output ID, template/version, sample file, reviewer, review date, and outcome. Check long names and addresses, missing optional fields, repeated cargo and route rows, multiple currencies, page breaks, customer-safe pricing, immutable prior versions, failed render recovery and authorised download. Do not tick a row from a source template or local build alone; inspect the actual populated output and its entry in Documents.

The Documents library is an operator-facing read projection over existing records. Dexter chat and Watching for you do not yet expose this combined list or template publication; they must continue to use their existing Quote, Booking, Customs and finance domains and must not claim that a file was reviewed or published from this projection. This is an explicit parity exception until document-level source identifiers and deterministic publication events are added to Dexter.
