## Template and evidence contract for the enquiry to invoice journey

| Stage | Required evidence or output | Source record and required information | Current path / work to verify | Acceptance sample |
| --- | --- | --- | --- | --- |
| Enquiry | Original message and attachments | Inbox enquiry: sender, received time, original file names, customer and reference | Retain originals; link to the resulting Quote and Booking without changing them | Sanitised email with one attachment |
| Quote sent | Exact customer PDF sent | Quote version: customer, route, cargo, service scope, selling charges, currency, terms and validity | Existing Quote PDF generator and private stored object; keep that exact version on the Quote record | Sent Quote with multiple charges |
| Quote accepted | Accepted version and response evidence | Customer response linked to the sent Quote version and converted Booking | Existing response and conversion workflow; retain the immutable PDF and acceptance event | Accepted version followed by Booking conversion |
| Booking | Booking Confirmation PDF | Booking: customer, shipper, consignee, service legs, route, cargo, schedule, instructions and permitted selling prices | `JOB_CONFIRMATION` Carbone source is an unpublished candidate; review and publish after scenario checks | One and multiple cargo/route lines; provisional and confirmed price |
| Customs handover | Instructions plus relevant commercial invoice, packing list and transport evidence | Booking and Customs: parties, goods, values, origin, HS codes, regime, transport, source file identity | Assemble from existing Booking/Customs documents; create a customer-safe instruction template where required | Export handover with supporting files |
| Customs outcome | Provider declaration copy and status | Customs declaration: MRN/reference, accepted data, provider status and received document | Existing iCustoms document path and Carbone customs templates; show the provider copy when available | Sanitised import and export declaration copies |
| Billing demo | Printable view of the finance record | Sales invoice: legal entity, customer, Booking, charge lines, tax, currency, dates, number and posting status | Use the existing Finance print/proforma view while Finance is being developed separately. Commercial invoices supplied by a shipper are Customs supporting evidence, not Multideck's final freight invoice. Carrier bills of lading, waybills and transport orders are relevant supporting files or additional templates only when the service and mode require them.

For each accepted row record the source reference, output ID, template/version or existing generator, sample file, reviewer, review date, and outcome. The table above identifies which files need a maintained template and which are original evidence or outputs of an existing generator. Check long names and addresses, missing optional fields, repeated cargo and route rows, multiple currencies, page breaks, customer-safe pricing, immutable prior versions, failed render recovery and authorised download. Do not tick a row from a source template or local build alone; inspect the actual populated output on its source record. Record the reviewed template version in the Documents template library.

Documents is the central **template library**: approved managers can add a source, edit a draft through Word/Studio, preview against safe data, save a version and publish after review. Generated and received files remain on the enquiry, Quote, Booking, Customs or Finance record that owns them. Dexter chat and Watching for you do not yet manage template publication; they must not claim that a template was reviewed or published. This is an explicit parity exception until template-level approval events are added to Dexter.
